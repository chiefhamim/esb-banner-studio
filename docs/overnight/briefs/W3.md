## Mission

Generalize the Outreach autopilot engine (background scheduler, send windows, tray persistence, crash
recovery, append-only event ledger) into a distribution queue that schedules two **existing** actions at a
chosen Asia/Dhaka time: publish an approved story to the site, and post its banner + caption to Facebook.
**Extend the engine; do not fork a second job system.** No new platforms: Telegram / X / LinkedIn get a
documented integration boundary in your report only. Queue view with scheduled / running / done / failed,
cancel, and an approval gate — nothing fires without an explicit approved status; an idempotency key per
(story, destination) so a crash-restart never double-publishes.

## Architecture (decided — build to this)

- The **main process** schedules, persists, ledgers and gates (`electron/outreach-engine.cjs`,
  `outreach-jobs.cjs`, `outreach-schedule.cjs`, `outreach-events.cjs`, `outreach-tray.cjs`). The **renderer
  executes**: only it can render the banner (Canvas 2D) and holds the site session and Page token in its own
  storage. So a distribution job is: engine decides "fire now" → pushes `{ kind: 'distribute.fire', jobId, key,
  action, storyId, dry }` on the existing `onOutreach` push channel → the renderer runs the existing publish /
  post functions (dry-run when `dry`, which the engine sets from `ESB_OUTREACH_DRYRUN=1`) → reports back once
  through one new IPC `esb:outreach-distribute-result` `{ jobId, key, ok, detail }` validated in
  `electron/outreach-guard.cjs`.
- Job model: new job kind `distribute` in `outreach-jobs.cjs`: `{ kind: 'distribute', action: 'publish-site' |
  'post-facebook', storyId, slug, headline, fireAt (epoch ms from a Dhaka wall time), approved: boolean,
  key: 'dist:<storyId>:<action>', status: queued | running | done | failed | cancelled, attempt, result }`.
- Exactly-once: the ledger (`outreach-events.cjs`) records `distribute.fire` with the key **before** the push;
  a key already `running` or `done` is refused (`distribute.skip` event with reason). On relaunch, a job found
  `running` with no result becomes `failed` with reason `interrupted — check the site before scheduling again`;
  it is **never** auto-refired (publishing is not idempotent on the far side). Re-submitting the same key is
  refused until the editor cancels the failed job explicitly.
- Approval gate: `approved` can only be set by the renderer through the existing control IPC
  (`outreachJobControl(jobId, 'release')` → approved; `'hold'` → unapproved); the engine ignores unapproved jobs.
- Tray: `isActive()` in the engine must also count approved `distribute` jobs that are queued or running, so
  closing the window hides to the tray and the renderer stays alive to execute. If the app is not running at
  `fireAt`, the job fires at the next launch only if still within a 2-hour grace window; otherwise it becomes
  `failed: missed` — say this in the UI.
- Time: Dhaka wall time → epoch via the engine's existing schedule helpers (`outreach-schedule.cjs` has the
  Asia/Dhaka window maths; reuse, do not duplicate); DST-free zone, but test the day boundary and the
  window-edge cases anyway.

## Build

1. Engine: job kind, key ledger, approval gate, `isActive()` extension, push + result IPC, relaunch recovery.
2. Renderer executor (`src/outreach/distribution.ts`): subscribes to the push, runs the existing publish/post
   code paths with the story from the queue, honours `dry` (dry-run = render and build the payload, call nothing
   remote, report `ok: true, detail: 'dry-run'`), reports once.
3. UI: in `PublishDialog.tsx` a **Schedule for later** control (date + time in Dhaka, `DatePicker` + a time
   `Select` on 15-minute steps; actions Site / Facebook ticks) that creates jobs (unapproved) and a clear
   **Approve** step; in the Activity desk a **Queue** tab listing jobs with status chips, fire time, key, and
   **Cancel** / **Approve** / **Hold** actions (`btn sm`); the Telegram/X/LinkedIn boundary is text in your
   report, not UI.
4. CSS under `/* W3 — distribution */` in `src/styles/outreach-activity.css`, tokens only.
