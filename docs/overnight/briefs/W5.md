## Gate first (time-boxed: 90 minutes from your first command)

Prove, offline, that two saved fixture feeds parse to title/link/date/source with the renderer's `DOMParser`,
and that the existing fetch bridge can carry feed XML: `window.esb.fetchUrl(url, { timeoutMs, allowedTypes })`
(`src/esb.d.ts`, main-process handler in `electron/main.cjs` → `electron/net-guard.cjs` `safeFetch`). Read what
`allowedTypes` accepts and what `net-guard` does with `application/rss+xml`, `application/atom+xml`,
`text/xml`, `application/xml`. Write the two fixtures yourself (`tools/fixtures/feeds/rss2.xml`,
`tools/fixtures/feeds/atom.xml`, synthetic `example.com` content, 5 items each, one with CDATA, one with a
relative link, one without a date) plus `malformed.xml`. The spike passes when a vitest file parses both and
you have confirmed — by reading the code, not by fetching anything live — that feed content types pass the
bridge with its existing `allowedTypes` option. **If the bridge would need incompatible changes to
`net-guard.cjs` or new IPC, stop: write `docs/overnight/qa/W5-spike.md` with the evidence and end your run.**

## Mission (after the gate)

Inbound story discovery: a source registry (RSS/Atom/sitemap URLs) polled through the bridge, parsed to
title/link/date/source, deduplicated locally by normalized-title similarity (pure function — no AI), shown as
an editorial inbox where one click sends an item into the existing URL intake.

## Build

1. `src/editorial/wire.ts` (pure where possible):
   - Registry `esb-banner-studio/wire/sources/v1`: `{ id, url, name, kind: 'rss'|'atom'|'sitemap'|'auto',
     intervalMin (≥ 15), enabled, lastFetchedAt, lastOkAt, failures, nextAt, lastError }`.
   - `parseFeed(xml, sourceUrl)` → `{ items: { title, link (absolute), date (ISO or null), source }[], kind }`
     or `{ items: [], error }` for malformed input (never throws); RSS 2.0, Atom, sitemap `urlset`.
   - `normalizeTitle(t)` (lower-case, Bengali digits → ASCII, punctuation and whitespace collapsed) and
     `similar(a, b)` (equal after normalization, or token Jaccard ≥ 0.8) → `dedupe(items, existing)`.
   - Backoff: `nextDue(source, now, ok)` → ok: `now + intervalMin`; failure: `now + intervalMin × 2^failures`,
     capped at 6 h; `failures` resets on success.
   - Inbox `esb-banner-studio/wire/inbox/v1`: cap 300 newest-first, `dismissed` ids kept so a dismissed item
     does not come back; `pollDue(now, fetchFn)` polls only sources whose `nextAt ≤ now`, one at a time.
   - Zustand `useWire` store; the poll timer runs only while the Editorial desk is mounted (every 60 s check).
2. `src/editorial/WireInbox.tsx`: the **Wire** branch of the intake `Seg`: a source row editor (url, name,
   interval `Scrub`, enable `Switch`, remove), **Check now**, a filter field, and the inbox list — rows show
   title, source, relative time; row actions **Use this link** (fills `urlInput` and switches the `Seg` to
   Link — it does not fetch by itself) and dismiss. A source in backoff shows "Retrying in …" with the last
   structured error (`net-guard` message verbatim, as text). Empty: "No sources yet" with the add row.
3. CSS under `/* W5 — wire */` in `src/editorial/editorial.css`, tokens only.
