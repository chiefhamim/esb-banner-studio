## Findings

1. **non-blocking — the poll result over-counts "new" once the inbox is full, and capped-out items come back on every poll.**
   - Where: `src/editorial/wire.ts:438-440`. `report.added += fresh.length` is counted *before* `capInbox`, and `dedupe` only
     compares against the current inbox, so links the 300 cap dropped are offered again on the next poll.
   - Repro (probe step 4): three feeds with 10 000 + 50 + 200 items. The first Check now says
     `Checked 3 sources · 450 new.` while only 300 are stored. Make them due again, reload, Check now: `Checked 3 sources ·
     150 new.` The visible inbox is unchanged, because the 150 are re-added and then cut again.
   - Impact: with two or more large feeds (sitemaps often list 200+ URLs), every poll reports phantom "N new". That breaks
     the honest result line. The data is not harmed.
   - Fix: count only fresh ids that survive the cap, and keep a bounded "seen" link set (like `dismissed`) so capped-out
     links are not re-offered.
2. **non-blocking — a dismissed story can come back through another source.**
   - Where: `wire.ts:438`. Dismissal is by link only. `dedupe` runs against the inbox, which no longer holds the dismissed
     item, so a near-duplicate title from a second feed (different link) reappears.
   - Evidence: code reading. The brief only asks for dismissed ids, so this is not a spec breach.
   - Possible fix: keep the normalized titles of dismissed items and include them in `dedupe`'s `existing`.
3. **non-blocking — in a plain browser, Check now counts `no_bridge` as a failure.**
   - Where: `wire.ts:380-383` → `afterPoll`. Each click without the desktop bridge adds one to `failures` and pushes `nextAt`
     out (up to 6 h). The message itself is honest.
   - Low impact: the Electron profile's storage is separate from the browser's.
4. **non-blocking (layout) — nested scroll areas in the Wire panel.**
   - `.ed-wire-list` scrolls (min-height 160) inside `.ed-intake-body.ed-wire`, which also scrolls.
   - At 1366×768, opening Sources puts "Add source" below the fold. Measured: body scrollHeight/clientHeight 389/373 with

   - The last inbox row is cut mid-line with no fade (screenshots `editorial-wire__1366x768__*--after.png`). Everything is

     row width equal to list width (586/586). It is not W5's.
5. **non-blocking (cosmetic) — `plainText` keeps the text of a `<script>` element in a CDATA title.**

   to `dedupe`; stored by `dismiss` at `wire.ts:543`).
   - Dismissed titles are matched by the same Jaccard ≥ 0.8 rule for up to 2000 dismissals, from any source.
   - Example, by arithmetic: "Power Division load-shedding schedule for Dhaka on 3 November 2026" normalizes to 11
     tokens. The next day's "…on 4 November 2026" shares 10 of 12 tokens, a Jaccard of 0.83. Dismissing the first
     would silently hide every later one.
   - The same similarity rule already merged such titles against items still in the inbox in cycle 0. Dismissal now
     makes the hiding permanent.
