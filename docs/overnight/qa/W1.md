## Findings

1. **non-blocking — In single-quoted statements, a plural possessive ends the quote early.** `quoteLibrary.ts`, `closesAt`
   (`findQuotes`): a `’`/`'` after a letter and before a space is treated as the closing mark. So `‘We will review the
   generators’ contracts next month,’` yields the fragment `We will review the generators`, and `'The ministers' plan …'` yields
   `The ministers`.
   - The fragment is unattributed ("Speaker not named in the story") and is a real substring, so nothing is invented.
   - It is still a cut quotation that one click can put on a Quote card.
   - Exposure is narrow: Bengali sources use ‘ ’ but have no possessive apostrophe, and English drafts here normally use double
     quotes.

   Suggested fix: when a single-family close candidate is `s’`/`s'` followed by a space and a lower-case word, look for a later
   closing mark in the same paragraph that is followed by punctuation or the end of the line, and prefer that. Add cases adv 5
   and adv 6 to the unit test.
2. **non-blocking — Scare quotes become library entries.** `"energy transition roadmap"` and `'load-shedding era'` are kept as
   unattributed quotes. They are verbatim and honestly marked as having no named speaker, so this is noise rather than
   fabrication. Consider requiring that an unattributed quote contain a verb or run to sentence length (e.g. ≥ 4 words), or show
   a "phrase" label.
3. **non-blocking (carried from cycle 0; needs a D10 entry) — When IndexedDB really fails, the note still says "N added".**
   `outreach/idb.ts` `idbSet` never rejects. Probe P2a (IndexedDB `put` throws on entry keys): `"note":"4 added."` in the
   session, then `{"n":0,"empty":1}` after a reload. The index is not corrupted, because verify-on-read drops the rows. With no
   IndexedDB at all (P1), entries are memory-only and nothing tells the user. The fix belongs in `idb.ts`: a strict set that
   rejects on request or transaction error, or an availability probe. That file is outside W1's D10 scope, so the orchestrator
   decides.
4. **non-blocking (note) — The library lives in the `esb-outreach` IndexedDB database.** Clearing Outreach storage also clears
   the library.
