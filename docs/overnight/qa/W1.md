## Findings

1. **blocking — Narration is harvested and handed off as a verbatim quote, and the real quotes are lost.**
   `src/editorial/quoteLibrary.ts:291-306` takes quote facts from `extractFactTable`. That function (`facts.ts:75`) matches any
   opening mark against the first closing mark among `"”'’`, can run across paragraph breaks, and resumes scanning *after* each
   match. `isRealQuote` (`quoteLibrary.ts:229-239`) drops a mismatched pair but cannot recover the real quote, and the scan that
   carries on pairs the *closing* `"` of one quote with the *opening* `"` of the next. Probe `tools/out/qa/probe.test.ts`
   (`npx vitest run tools/out/qa/probe.test.ts --silent=false`) gives:
   - `"We need Bangladesh's gas fields to deliver more," said Karim Hossain, chairman of BPDB. Later the minister added: "Tariffs will stay where they are for now."`
     → the only quote harvested is `said Karim Hossain, chairman of BPDB. Later the minister added:`. Both real quotes are lost.
   - `The chairman said "the grid is stable and we are ready\n\nIn other news, "Load-shedding will end soon," said Rafiq Islam.`
     → harvested quote `the grid is stable and we are ready\n\nIn other news`, which spans two paragraphs. The real quote is lost.
   - `“Petrobangla’s new wells will add gas by winter,” said Nasrin Akter, …` → `[]`. A curly quote with an apostrophe is
     silently dropped.

   Apostrophes inside quotes (`Bangladesh's`, `country's`, `don't`) are routine in English copy, so this will happen on real
   stories. One click on **Use as quote banner** then publishes the narration as a quotation on a card. The builder's claim
   "real quotation-mark pairs only" is not true.

   **Fix (inside W1's files):** do the quote scan in `quoteLibrary.ts` instead of using the fact table's quote facts.
   - Work one paragraph at a time and never cross `\n`.
   - Pair `“` with `”`, and a straight `"` with the next straight `"` (or `”`).
   - Never treat `'` or `’` between letters as a delimiter.
   - Keep the 8–160 character bounds.

   Add the three strings above to `tools/unit/quote-library.test.ts`. Expected results: the first gives the two real quotes, the
   second gives only `Load-shedding will end soon`, the third gives the Petrobangla quote.

2. **non-blocking — When IndexedDB fails for real, the library still says "N added".** `outreach/idb.ts` (`idbSet`) never rejects.
   A failed `put` resolves `undefined`, and the value already sits in the memory map. So `saveMerge`'s failure branch
   (`quoteLibrary.ts:444`) and the red "could not be stored" note only ever fire with the injected test double.
   Probe P2a (`node tools/out/qa/probe-ui.mjs`) patches `IDBObjectStore.prototype.put` to throw `QuotaExceededError` on
   `/library/entry/` keys:
   - In the session: `{"n":4,"note":"4 added."}`.
   - After a reload: `{"n":0,"empty":1}`.

   The index stays consistent: verify-on-read drops the rows, so nothing is corrupted. But the success note appears for data that
   was never stored (COMMON hard rule 2). The same happens with no IndexedDB at all (P1: `"4 added."`, memory only, no notice that
   it will not survive a restart). The fix needs `idb.ts`, which is outside D10: either a strict `idbSet` that rejects on
   request/transaction error, or an `idbAvailable()` probe. That needs a D10 entry; it is not W1's to edit. The builder's report
   should list it as a limitation.
3. **non-blocking — A failed remove is silent.** `quoteLibrary.ts:569-571`: if the index write fails, `remove` returns with no
   message. P9: `{"still":true,"note":"4 added."}`. The row stays and the old harvest note is still shown. Show "Could not remove"
   or similar.
4. **non-blocking — A publish event with an unknown `storyId` is filed under that id using the desk's content.**
   `quoteLibrary.ts:548-551`: when `extra.storyId` is neither the active story nor a queued one, the desk's draft is harvested and
   labelled with the foreign storyId, headline, slug and URL.
   - In P8 the desk's entries already existed, so the event only appended `ghost-id` to their `alsoIn`.
   - With new desk content it would create entries whose provenance points at another article.

   Separately, an event for a *queued, non-active* story harvests that story's saved snapshot rather than the active story (P8:
   the `qa-other` quote, slug `other-slug`, correctly attributed; nothing leaked from the desk). That is a reasonable reading of
   D9 but differs from the brief's "harvest the active story", so record it in DECISIONS. Suggested: ignore events whose storyId
   is neither active nor queued.
5. **non-blocking (observation) — The library rides on the outreach database.** Entries are stored in the `esb-outreach` IndexedDB
   database / `kv` store via the shared helper. That is acceptable, but it is worth noting for anyone who clears Outreach data.
